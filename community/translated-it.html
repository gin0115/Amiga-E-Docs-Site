INTRODUCTION

Finally came the utility that all the programmers Amiga E dream- long time ago: a complete converter for GUI files created by GadTools Box v2.0+. In the Amiga E package there is a program that does this task (SrcGen) but it is so limited that often use it He meant to throw away an hour of my precious time... Here you go. the idea of creating a particularly comfortable one to use, but at the same time time able to create code more complete than that of SrcGen. Here below you can see some highlights of GTX-Conv:

  • is compatible with all Amiga v37+ (WB2.04+ )
  • Use all the potential of GadtoolsBox
  • is equipped with a comfortable GUI (converted with GTX-Conv :-)
  • creates code directly compiled or only routines that you
  • interest rates
  • the generated code is compatible with AmigaE v2.1b and v3. x
  • is fully configurable
  • does not require too much memory (60k should suffice... )
  • manages all tags, idcmps, gadgets etc. etc.
  • creates public screens, custom, or workbench...
  • generates font-sensitive code
  • can load GUIs tablets with PowerPacker
  • use system font or screen font
  • saves its configuration in a file
  • checkbox creation and scalable radio
  • NewLook use for menus
  • is fully manageable via keyboard
  • prints IDCMPs and flags extensively or not
  • creation of GETFILE gadget (only AmigaE 3.x) * (NEW) *
  • new hotkeys system for GTXConv * (NEW) *
  • manuals in English and Dutch * (NEW) *

Some things that will be implemented in future versions if the number of recordings will be sufficiently high:

  • complete multitasking between the windows generated * (ADDED) *
  • location of GTXConv * (ADDED) *

HARDWARE AND SOFTWARE REQUEST

This GTXConv version requires an Amiga 2.04+ (V37+) to work correctly. In the LIBS directory, you must find:

diskfont.library v37+ (free system)
Gadtools. library v37+ (free system, in ROM)
reqtools. library v37+ (supply)
powerpacker.library v35+ (supplied, optional)
keymap.library v37+ (free system, in ROM)
utilities. library v37+ (free system)

As far as memory rejuvenates, there should be no problem with only 100Kb free. The only problem could be defragmentation. memory: if something is not to be reset and considered. GTXConv creates in S: a config file for its settings. In case S: not be present the file will be saved in SYS:. Make sure these two logical devices are writing sprouts. To be able to complete the code using GETFILE gadget you have to copy in EMODULES: the form 'boopsi.m' and use AmigaE v3+.

IMPLEMENTATION TAGS

After hours and hours of hungry search to find out if you say 'i tag' or 'the tag' (for personal choice I preferred the male), I managed to compile a list of tags currently recognized by GTXConv (they are practically all those managed by GadToolsBox). Please note that that some for V39 or more are not supported as not recognized by GadToolsBox. If there are no tags, I assure you that they will come implemented in a future version of GTXConv, for now Welcome. . :).

The only problems can be caused by GTLV LABELS and also by GTLV SHOWSELECTED, both tags for ListView gadgets. As from GadtoolsBox you can't choose the StringGadget for the second tag, GTXConv cannot know which gadget you refer to to to show off choice. If set, however, GTXConv will show it in the tag list with argument 0; to assign it to a StringGadget just replace zero with the pointer at the StringGadget (i.e. its label).
