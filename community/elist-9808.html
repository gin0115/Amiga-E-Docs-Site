word-aligned. OBJECT itself is word-aligned too. So to make "written"
word-aligned compiler have to add a byte to "sysopname". In other
words - every part of OBJECT has always size rounded up to word.

Probably you want that the MOVE instructions move to a hardware
register. However, DEF creates variables. If you move to it,
the value of the variable is changed. The E equivalent of EQU is
CONST.

A busy-waiting loop is a bad idea in a multi-tasking system.

stack frames using the LINK instruction. If you use the E RETURN
statement everything is okay. It sets the return values to 0,
unless you use RETURN D0.

> >And BTW, is tanh() and atan() the same function?

No.a:=atan(x) is the inverse function of x:=tan(a), which does a
trigonometric
tangent. (like sin() and cos(), which are also trig functions, and have
asin() and
acos() as inverses).
sinh(), cosh() and tanh() are hyperbolic functions, which operate on an
hyperbola
instead of a circle. If you want to see it, try drawing points at
coordinates
(cos(a);sin(a)) when a is between zero and two pi. This will draw a circle.
If you do the same with (cosh(a);sinh(a)), you will get an hyperbola.
Their inverse functions are, respectively, asinh(), acosh() and atanh().
Hyperbolic functions are quite rarely used.

Mmmhh. If I understand you correctly, you wanna save
some (different) objects into an IFF file, right?
First, you probably can't use CollectionItems
via iffparse.library/FindCollection() this enables
you only to get lists of certain chunk datas.
Eq. name_list=FindCollection(iff, "NAME", "BOXS")
    will return a list of datas of all NAME-chunks.
    Same for "COOR" and "SIZE", ...
The problem: You don't know which box has not SIZE chunk!

On solution is to put an marker between the objects.
The file structure then looks like:
        FORM BOXS
                NAME BOXS "1.name"
                SIZE BOXS 1
                STOP BOXS
                NAME BOXS "2.name"
                COOR BOXS 1,2,3
                STOP BOXS
        ...

Or you use an LIST chunk. I am not sure if you can create
it automatical with iffparse.library but the file then
should look like:

        LIST BOXS
                FORM BOXS
                        NAME BOXS "1.name"
                        SIZE BOXS 1
                FORM BOXS
                        NAME BOXS "2.name"
                        COOR BOXS 1,2,3

Both methods may be parsed semi-automatical by setting the
stop-chunks to ("STOP","BOXS") or ("FORM","BOXS") and prop-chunks
to ("NAME","BOXS"), .... You can then let iffparse.library parse
every object data and then stop. Now you create your box by finding
the prop-chunks. Then clear all found chunks and continue.

Hope this helps a little bit.
PS: If you wanna store datas of OOP-objects I recommend to create
    an single chunk and store the datas manually. I can post examples
    if wanted.

Well, it is a difference whether you don't understand the ReadArgs()
function
or the argument syntax.

In the second case try this:

"FONT,NEWICONMODE/S,XPOS/N,YPOS/N"

Some words about this:

FONT is a string, so no special definition is required
NEWICONMODE is a switch, so we set mode SWITCH by adding "/S"
XPOS AND YPOS are both numbers, so we set mode NUMBER by adding "/N"

you can also set several modes at the same time, especially useful with
ALWAYS ("/A") and KEYWORD ("/K")

ALWAYS means that if the argument is not present, reading the
argument line will fail.

KEYWORD means that the user always has to specify the argument together
with the keyword, e.g. he must write "FONT=topaz.8", while without "/K" he
might just write "topaz.8" either.

Combined modes look like this:

FONT/A/K,NEWICONMODE/S,XPOS/N/K,YPOS/N/K

Now, the font name *always* has to be specified with keyword,
XPOS and YPOS are still optional, but have to be written
together with the keyword not to mix them up.

(e.g. "YPOS=10 XPOS=20", just "10 20" would not be legal)

For further details look at the autodocs dos/ReadArgs()

Hope it helps. :-)

prefix to them.

(Declare filereq with: DEF filereq:PTR TO filerequester,
and str is a STRING var)

IF (filereq:=Mui_AllocAslRequest(ASL_FILEREQUEST,
                            [ASL_HAIL,      'Title',
                             ASL_OKTEXT,    'Text in ok button',
                            ASL_FILE,      'DefFile',
                             NIL])) = NIL
    Mui_RequestA(app,window,0,'Title',NIL,'Can''t allocate AslRequest',NIL)
ELSE
    IF Mui_AslRequest(filereq,NIL)
        StrCopy(str,filereq.drawer)
        AddPart(str,filereq.file,StrMax(str))
        SetStr(str,StrLen(str))
        /*Use str here, it contains the full path of the file*/
   ENDIF
    Mui_FreeAslRequest(filereq)
ENDIF

Note that you may allocate an asl request and use it several times without

Objects are meant for storage in memory, so storing INTs or LONGs on odd
boundaries is useless. The ODD keyword can be emulated in the way that is
used in the CIA structure. This does not cause any trouble. It looks a bit

The method without objects:

Instead of the Write() function, it is better to use FPutC(), FWrite(),
VFPrintf(), FPuts() etc. if the length is usually less than 208 bytes. This=

reduces some overhead. It's still quite slow. Do not switch between F#?()
and Write() without doing a Flush() in between.
